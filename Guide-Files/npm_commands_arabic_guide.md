## 1. المفاهيم الأساسية

| الملف / المجلد | الوظيفة |
|---|---|
| **`npm`** | اختصار لـ *Node Package Manager*، وهو مدير الحزم الذي ينزل لك المكتبات والأدوات ويدير تشغيل السكربتات. |
| **`package.json`** | بمثابة "بطاقة الهوية" للمشروع؛ يحتوي على اسم المشروع، المكتبات التي يعتمد عليها، والسكربتات (`scripts`) المخصصة للتشغيل. |
| **`package-lock.json`** | يسجل بدقة متناهية الأرقام الدقيقة لكل إصدار فرعي تم تنزيله لضمان تطابق البيئة بين جهازك والإنتاج. لا تقم بتعديله يدوياً. |
| **`node_modules`** | المجلد الفعلي الذي يحتوي على أكواد كل المكتبات التي قمت بتثبيتها. حجمه كبير ولا يُرفع على GitHub (موجود في `.gitignore`). |
| **`.env.local`** | ملف المتغيرات السرية والبيئية (مفاتيح YouTube API، Gemini API، رابط قاعدة البيانات). لا يُرفع على GitHub مطلقاً. |

## 2. أوامر المشروع الخاصة (`npm run ...`)

هذه الأوامر مُعرفة خصيصاً داخل ملف `package.json` في هذا المشروع لتسهيل المهام المعقدة:

### 1. تشغيل سيرفر التطوير المحلي
```bash
npm run dev
```
- **ماذا يفعل؟** يشغل تطبيق Next.js في وضع التطوير مع التحديث اللحظي (Fast Refresh) عبر محرك Turbopack.
- **الرابط الافتراضي:** `http://localhost:3000` (أو منفذ آخر مثل 3001 إذا كان 3000 مشغولاً).
- **متى تستخدمه؟** طوال فترة كتابة الكود وتجربة التعديلات في المتصفح.

---

### 2. فحص الأخطاء والتنسيق (ESLint)
```bash
npm run lint
```
- **ماذا يفعل؟** يفحص جميع ملفات المشروع عبر **ESLint** لاكتشاف أخطاء React (مثل أخطاء الـ hooks، المتغيرات غير المستخدمة، الأقواس غير المغلقة).
- **النتيجة المطلوبة دائماً:** خروج نظيف بدون أخطاء (Code 0).

---

### 3. فحص الأنواع الصارم (TypeScript Typecheck)
```bash
npm run typecheck
```
- **ماذا يفعل؟** يقوم بخطوتين متتاليتين:
  1. يُحدث كود عميل Prisma عبر `prisma generate`.
  2. يُشغل فاحص الأنواع الصارم `tsc --noEmit --incremental false` للتأكد من عدم وجود أي خطأ في Types أو Props أو Interfaces في الكود.
- **ميزته:** يكتشف الأخطاء قبل محاولة بناء المشروع.

---

### 4. التحقق من متغيرات البيئة السرية
```bash
npm run env:validate
```
- **ماذا يفعل؟** يشغل سكربت الحماية `scripts/app-validate-env.mjs`.
- **فائدته:** يتأكد من وجود المتغيرات المطلوبة للتشغيل مع حجب وطمس أي سر أو Password تلقائياً لمنع تسريبها في السجلات.

---

### 5. بناء نسخة الإنتاج النهائية
```bash
npm run build
```
- **ماذا يفعل؟** يقوم بالبناء الكامل للإنتاج:
  1. يفحص المتغيرات البيئية (`npm run env:validate`).
  2. يُنشئ عميل Prisma (`npm run db:generate`).
  3. يبني التطبيق بأقصى درجات الضغط والتحسين عبر `next build` بمحرك Turbopack.
- **متى تستخدمه؟** قبل رفع أي كود على سيرفر الإنتاج (مثل Vercel) للتأكد من أن البناء سينجح 100%.

---

### 6. تشغيل نسخة الإنتاج محلياً
```bash
npm run start
```
- **ماذا يفعل؟** يُشغل السيرفر المعتمد على مجلد البناء `.next` الناتج من أمر `npm run build`.
- **ملاحظة:** لا يعمل إلا بعد تنفيذ `npm run build` أولاً. يستخدم لاختبار سرعة وأداء التطبيق كما لو كان على سيرفر حقيقي.

---

### 7. الفحص الثلاثي الشامل (Verify All)
```bash
npm run verify
```
- **ماذا يفعل؟** يشغل السلسلة الكاملة بالتتابع:
  `npm run lint && npm run typecheck && npm run build`
- **فائدته:** يضمن لك بنسبة 100% أن الكود خالٍ من أي عيب برمجي أو خطأ بناء قبل عمل Git Commit و Push.

## 3. أوامر قاعدة البيانات و Prisma

المشروع يعتمد على **Prisma 7** مع قاعدة بيانات Supabase PostgreSQL:

```bash
# 1. توليد عميل Prisma وتحديث الموديلات البرمجية
npm run db:generate

# 2. التحقق من صحة ملف المخطط (prisma/schema.prisma) وصحة المتغيرات
npm run db:validate

# 3. فحص حالة الـ Migrations هل مطبقة على قاعدة البيانات أم لا
npm run db:status

# 4. تطبيق الـ Migrations بحذر على قاعدة البيانات (محمي بحاجز أمان)
# في PowerShell:
$env:CONFIRM_DB_APPLY="true"; npm run db:apply
```

### فتح لوحة تحكم رسومية لتصفح البيانات (Prisma Studio)
```bash
npx prisma studio
```
- **ماذا يفعل؟** يفتح صفحة ويب محلية على `http://localhost:5555` تمكنك من رؤية الجداول والصفوف وتعديل البيانات وحذفها بصرياً بكل سهولة!

## 4. أوامر إدارة المكتبات والحزم (Dependencies)

### تثبيت جميع مكتبات المشروع (عند سحب مشروع جديد أو تنزيله)
```bash
npm install
# أو باختصار:
npm i
```

---

### تثبيت مكتبة جديدة للإنتاج (مثل zod, lucide-react, zustand)
```bash
npm install <package-name>
# مثال:
npm install zustand
```
- تُضاف المكتبة تلقائياً في قسم `"dependencies"` داخل `package.json`.

---

### تثبيت مكتبة لأغراض التطوير فقط (مثل types, linters)
```bash
npm install -D <package-name>
# أو:
npm install --save-dev <package-name>
# مثال:
npm install -D @types/node
```
- تُضاف المكتبة في قسم `"devDependencies"`.

---

### حذف مكتبة لم تعد بحاجة إليها
```bash
npm uninstall <package-name>
# مثال:
npm uninstall lodash
```

---

### معرفة المكتبات التي تتوفر لها تحديثات جديدة
```bash
npm outdated
```
- يعرض جدولاً يوضح: الإصدار الحالي عندك (`Current`)، الإصدار المسموح به (`Wanted`)، وأحدث إصدار موجود على الإنترنت (`Latest`).

---

### تحديث المكتبات إلى الإصدارات المسموحة
```bash
npm update
```

---

### عرض قائمة الحزم المثبتة في المشروع بدون تفاصيل فرعية طويلة
```bash
npm list --depth=0
```

## 5. أوامر التشغيل المباشر عبر `npx`

أداة `npx` تأتي مدمجة مع `npm` وتسمح بتشغيل أدوات وحزم برمجية فوراً دون الحاجة لتثبيتها كأمر عالمي في نظام التشغيل:

```bash
# فحص كود TypeScript يدوي بدون إنشاء ملفات js
npx tsc --noEmit

# عرض معلومات بيئة Next.js ونظام التشغيل والمتصفحات
npx next info

# فحص الثغرات الأمنية في الحزم
npm audit

# محاولة إصلاح الثغرات الأمنية تلقائياً دون كسر النسخ
npm audit fix
```

## 6. أوامر الصيانة، الكاش، وحل المشاكل المستعصية (Troubleshooting)

كثيراً ما تحدث مشاكل بسبب تعليق الكاش، أو فشل تثبيت جزئي، أو خطأ في ملفات Turbopack / Next.js المؤقتة. إليك خطوات الحل بالترتيب:

### المشكلة 1: كاش npm معطل أو تالف
```bash
npm cache clean --force
```

---

### المشكلة 2: تضارب إصدارات المكتبات (Peer Dependencies Conflict)
إذا حاولت تثبيت مكتبة وظهر لك خطأ `ERESOLVE unable to resolve dependency tree`:
```bash
npm install <package-name> --legacy-peer-deps
```

---

### المشكلة 3: التثبيت الصارم النظيف (Clean Install)
```bash
npm ci
```
- **ماذا يفعل؟** يحذف `node_modules` داخلياً ويقوم بتثبيت الحزم بالملي وفق ملف `package-lock.json`. ممتاز لبيئات السيرفرات وللتأكد من عدم وجود تباين.

---

### المشكلة 4: الحل الجذري الشامل عند حدوث أخطاء غريبة في البناء أو التشغيل
إذا واجهتك أخطاء غير مفهومة في Next.js أو ملفات تالفة:

#### على نظام Windows (باستخدام PowerShell):
```powershell
# 1. إيقاف أي سيرفر يعمل (Ctrl + C)
# 2. حذف مجلدات الكاش والمكتبات
Remove-Item -Recurse -Force .next, node_modules

# 3. تنظيف كاش npm
npm cache clean --force

# 4. إعادة التثبيت بالكامل
npm install

# 5. إعادة بناء المشروع وفحصه
npm run verify
```

#### على أنظمة Linux / macOS (أو Git Bash):
```bash
rm -rf .next node_modules
npm cache clean --force
npm install
npm run verify
```

## 7. مفاتيح واختصارات سطر الأوامر المهمة (CLI Flags)

| المفتاح (Flag) | ماذا يفعل؟ | مثال |
|---|---|---|
| `-D` أو `--save-dev` | يحفظ الحزمة كـ devDependency | `npm i -D typescript` |
| `-g` أو `--global` | يثبت الأداة على مستوى نظام التشغيل بالكامل | `npm i -g vercel` |
| `--force` | يجبر npm على إكمال الأمر وتجاوز التحذيرات | `npm i --force` |
| `--legacy-peer-deps` | يتجاهل تعارضات إصدارات الـ peer dependencies | `npm i package --legacy-peer-deps` |
| `--dry-run` | يجرب تشغيل الأمر دون عمل أي تعديل فعلي للملفات | `npm publish --dry-run` |

## 8. نصائح ذهبية لمشاريع Next.js الحديثة (2026 Best Practices)

1. **لا تعدل `package-lock.json` يدوياً مطلقاً:** دع npm يديره لتجنب مشاكل المزامنة بين المطورين وسيرفرات الاستضافة (Vercel).
2. **شغل `npm run lint` و `npm run typecheck` دائماً قبل عمل Commit:** هذا يمنع رفع أي كود قد يفشل في Vercel Build.
3. **لا تضع الأسرار في الكود:** احتفظ بجميع مفاتيحك (`YOUTUBE_API_KEY`, `GEMINI_API_KEY`, `DATABASE_URL`) في ملف `.env.local` فقط.
4. **تأكد دائماً من توليد Prisma:** إذا قمت بتعديل `prisma/schema.prisma`، نفذ فوراً `npm run db:generate` حتى يفهم TypeScript الموديلات الجديدة وتعمل الإكمال التلقائي (Autocomplete).

## 9. جدول الملخص السريع (Quick Cheatsheet)

احفظ هذه السطور عندك للاستخدام السريع:

```text
========================================================================
⚡ الأوامر اليومية الأكثر استخداماً:
------------------------------------------------------------------------
npm run dev           # تشغيل المشروع محلياً للتطوير (http://localhost:3000)
npm run lint          # فحص أخطاء الكود و React Hooks عبر ESLint
npm run typecheck     # فحص أنواع TypeScript وتوليد عميل Prisma
npm run build         # بناء نسخة الإنتاج المحسنة
npm run start         # تشغيل نسخة الإنتاج بعد البناء
npm run verify        # فحص شامل (lint + typecheck + build) دفعة واحدة
------------------------------------------------------------------------
🗄️ أوامر قاعدة البيانات و Prisma:
------------------------------------------------------------------------
npm run db:generate   # توليد Prisma Client بعد تعديل المخطط
npm run db:validate   # التحقق من صحة ملف prisma/schema.prisma
npx prisma studio     # فتح لوحة تحكم رسومية لتعديل البيانات في المتصفح
------------------------------------------------------------------------
📦 أوامر إدارة الحزم:
------------------------------------------------------------------------
npm install           # تثبيت جميع حزم المشروع
npm install <name>    # تثبيت مكتبة للإنتاج
npm install -D <name> # تثبيت مكتبة للتطوير فقط
npm uninstall <name>  # حذف مكتبة
npm outdated          # استعراض التحديثات المتاحة للمكتبات
------------------------------------------------------------------------
🧹 أوامر الصيانة وحل الأخطاء:
------------------------------------------------------------------------
npm cache clean --force               # تنظيف كاش npm
npm i --legacy-peer-deps              # حل تعارضات إصدارات الحزم
Remove-Item -Recurse -Force .next     # حذف كاش Next.js القديم (PowerShell)
========================================================================
```
